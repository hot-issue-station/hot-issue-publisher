# 덕심저장소 쇼츠 예약 업로더 (1차, 설계 + 뼈대 코드)

쇼츠 공장(`shorts_factory.py`)이 만든 영상 하나를 **유튜브·틱톡·인스타그램·페이스북·X**에 같은 시각으로 예약한다.
비용 0원(유료 API 없음). 대표 데스크톱(윈도우)의 크롬을 Playwright(파이썬)로 화면 조작한다.

> **기본값은 '확인 모드'**: 프로그램은 각 사이트의 **최종 예약 단추 바로 앞에서 멈추고**, 대표가 화면을 본 뒤 직접 누른다.
> 자동으로 누르는 모드(`--final-click`)도 있지만 권장하지 않는다(아래 「이용약관 위험」).

## 1. 전체 흐름

```
기획 JSON ──▶ shorts_factory.py ──▶ out/<이름>.mp4 · _thumb.png · _게시문구.txt
                                          │
                                          ▼
                 upload_plan.py  (점검 도구, 인터넷 안 씀)
                 · 사이트별 제목·설명·태그·예약 시각·파일 표
                 · 5줄 점검표 + 길이·개수 제한 + 빠진 파일
                 · ❌ 하나라도 있으면 여기서 끝 (올리지 않음)
                                          │ 통과
                                          ▼
                 run.py  ──▶ 크롬(업로드 전용 프로필) 열기
                    ├ youtube.py   유튜브 Studio
                    ├ tiktok.py    틱톡 Studio
                    ├ meta.py      비즈니스 스위트 → 인스타+페이스북 동시
                    └ x.py         X 게시물 예약
                    · 단계마다 스크린샷 → logs/<시각>_<이름>_<사이트>/
                    · 로그인·봇 확인 화면 → 멈추고 대표에게 넘김
                    · 최종 예약 단추 직전 → 멈춤(확인 모드)
                                          │
                                          ▼
                 대표: 화면 확인 → 직접 [예약] → '완료' 입력
                 유튜브 첫 댓글: 공개된 뒤 대표가 확인하고 달아 고정
```

게시 문구는 **`out/<이름>_게시문구.txt`를 우선** 쓴다(대표가 고쳤으면 고친 글로). 없으면 기획 JSON의 `post` 칸으로 같은 형식을 만든다.
`#shorts`는 유튜브 전용이라 틱톡·인스타·페이스북·X 글에서는 자동으로 뺀다.

예약 시각: **출근 07:30 · 점심 12:00 · 퇴근 18:30 (서울 시간)** 중 고른다. 안 고르면 지금부터 20분 이상 남은 가장 가까운 시간대.
기획 JSON에 `"upload": {"slot": "퇴근", "date": "2026-11-12"}`처럼 적어 둘 수도 있다.

## 2. 파일

| 파일 | 하는 일 |
|---|---|
| `upload_plan.py` | 점검 도구. `python upload_plan.py 기획.json --slot 점심` → 표 + 빠진 것. `out/<이름>_업로드계획.json` 생성. 끝 코드 0=통과, 1=빠짐 |
| `run.py` | 실행기. 점검 → 통과 시 크롬 열고 사이트 차례로 진행 → `logs/<이름>_결과.json` |
| `common.py` | 같이 쓰는 도구: 로그인·캡차 감지 멈춤, 화면 글자로 찾기, 스크린샷, 비밀번호 칸 쓰기 거부, 확인 모드 |
| `youtube.py` `tiktok.py` `meta.py` `x.py` | 사이트별 조작 순서(뼈대). 확실하지 않은 선택자는 `TODO` |
| `setup.bat` | 처음 한 번: Playwright 설치 |
| `login_once.bat` | 처음 한 번(또는 로그인이 풀렸을 때): 업로드 전용 크롬을 열어 대표가 직접 로그인 |
| `check_plan.bat` | 기획 JSON을 끌어다 놓으면 점검표만 보여 줌(업로드 안 함) |
| `run_confirm.bat` | 기획 JSON을 끌어다 놓으면 확인 모드로 예약 진행 |

## 4. 멈추는 경우 (우회하지 않음)

| 상황 | 프로그램이 하는 일 |
|---|---|
| 로그인 화면(주소에 login/signin, 비밀번호 칸) | 스크린샷 → "대표님이 로그인해 주세요" → 대표가 끝내고 엔터 → 다시 확인 후 계속 |
| 봇 확인·캡차·퍼즐·문자 인증·"비정상적인 활동" | 스크린샷 → **멈춤**. 대표가 직접 처리. **풀거나 피하는 코드는 만들지 않는다** |
| 비밀번호 칸에 글을 쓰려 함 | 즉시 중단(설계상 금지) |
| 단추·칸을 못 찾음(화면 문구 바뀜) | 스크린샷 → 대표가 그 단계만 직접 → 엔터로 계속 / '건너뛰기' / '중단' |
| 한 사이트 오류 | 그 사이트만 기록하고 다음 사이트로 |

자동화 흔적을 숨기는 설정(스텔스 플러그인, `--enable-automation` 제거 등)은 쓰지 않는다. 크롬 상단에 "자동화된 테스트 소프트웨어에 의해 제어되고 있습니다"가 보이는 것이 정상이다.
봇 확인이 **같은 사이트에서 두 번 이상** 나오면 그 사이트는 자동 진행을 쉬고 손으로 올린다.

## 5. 업로드 직전 5줄 점검표 (통과해야만 진행)

`shorts_factory.checklist`와 **같은 함수**를 그대로 불러 쓴다(항목이 따로 놀지 않게).

1. 끝 화면(구독·좋아요·알림) 3초 이상
2. 배경음악 들어감
3. 출처·기준 표시
4. 숫자 확인 기록(확인한 곳·시각)
5. 썸네일·제목·소개글·첫 댓글

추가로 잡는 것: 영상·썸네일·게시문구 파일 없음, 유튜브 제목 100자·설명 5000자·태그 500자·썸네일 2MB, 틱톡 설명 2200자·10일, 인스타 설명 2200자·해시태그 30개,
X 280(한글 2), 영상 길이(쇼츠·릴스 3분, X 2분 20초), 예약 시각이 지금부터 20분 안이거나 지남, 기획 JSON과 영상 길이가 다름(영상을 다시 안 만든 경우).

## 6. 이용약관상 자동화 위험 (솔직하게)

| 사이트 | 약관 | 위험 |
|---|---|---|
| 유튜브 | 공식 API나 허락된 경우가 아니면 자동 수단으로 서비스에 접근하는 것을 금지 | 업로드 제한·계정 확인 요구 가능. 정식 대안은 아래 Data API |
| 틱톡 | 자동화된 수단으로 서비스에 접근·이용하는 것 금지 | 봇 확인이 가장 자주 나옴. 도달 제한·계정 제한 가능 |
| 메타(인스타·페이스북) | 허락 없이 자동 수단으로 접근 금지 | 반복 시 "자동화된 활동" 경고·기능 제한 가능 |
| X | API 밖의 자동 조작·스크립트 게시를 명시적으로 금지(가장 엄격) | 계정 잠금·정지 가능 |

정리: **화면 조작 자동화는 네 곳 모두 약관상 회색~위반 지대**이고, 계정 제한이 생기면 덕심저장소 전체가 멈춘다.
그래서 이 프로그램은 ① 하루 3회·영상 1개씩만(대량 반복 없음) ② **예약 단추는 대표가 직접**(확인 모드 기본) ③ 봇 확인이 나오면 즉시 멈춤 ④ 흔적 숨기기 없음 — 으로 위험을 줄이지만 **0으로 만들지는 못한다**.
사람이 하던 일을 덜어 주는 '입력 도우미'로 쓰고, 경고가 한 번이라도 오면 그 사이트는 손 업로드로 돌아간다.

## 7. 유튜브 대안: 무료 YouTube Data API (비교만)

| | 화면 조작(지금 방식) | YouTube Data API v3 (OAuth) |
|---|---|---|
| 비용 | 0원 | 0원(하루 할당량 10,000점) |
| 할당량 | 없음 | 업로드 1회 약 1,600점 + 썸네일 50점(공식 문서 기준, 바뀔 수 있음) → **하루 약 6개** (하루 3회면 충분) |
| 약관 | 회색 지대 | **정식 허용 방식** |
| 예약 | 화면에서 날짜·시간 선택 | `privacyStatus=private` + `publishAt` 로 예약 |
| 화면 바뀜 영향 | 큼(선택자 고장) | 거의 없음 |
| 처음 준비 | 크롬 로그인만 | Google Cloud 프로젝트 만들기 → API 켜기 → OAuth 동의 화면 → 대표 계정으로 한 번 허락 |
| 큰 함정 | — | **심사(감사)를 안 받은 프로젝트로 올린 영상은 '비공개'로 잠김** → 예약 공개가 안 됨. 무료 심사 신청 필요(몇 주 걸릴 수 있음) |
| 썸네일 | 화면에서 | 채널 휴대폰 인증 필요(화면 방식과 같음) |
| 첫 댓글 고정 | 사람 | API로 댓글은 달 수 있지만 **고정은 API에 없음** → 사람 |

권장: 1차는 화면 조작(확인 모드)으로 시작하고, 유튜브는 Data API 심사를 병행 신청해 통과되면 API로 바꾼다(유튜브가 가장 오래 쓸 채널이므로).
(참고: 틱톡·인스타·페이스북·X도 공식 API가 있지만 앱 심사, 비공개 제한, 유료 등급 등 조건이 붙어 지금 단계에선 비교하지 않음.)

## 8. 처음 한 번 (대표 데스크톱)

1. `setup.bat` 두 번 클릭 → 설치 끝날 때까지 기다림(파이썬은 이미 공장용으로 설치돼 있어야 함).
2. `login_once.bat` 두 번 클릭 → 새 크롬 창의 탭 4개(유튜브 Studio·틱톡 Studio·비즈니스 스위트·X)에서 **대표가 직접 로그인** → 크롬 창 닫기.
   - 평소 쓰는 크롬과 **따로 된 업로드 전용 프로필**(`%LOCALAPPDATA%\DuksimUploader\chrome_profile`)이다. 평소 프로필 복사는 윈도우 크롬이 로그인 정보를 원래 위치에 묶어 암호화해서 풀리는 경우가 많아 쓰지 않는다.
   - 이 창은 프로그램이 조작하는 창이 아니라 **일반 크롬**이라 구글 로그인이 막히지 않는다.
3. 시험: 기획 JSON을 `check_plan.bat` 위에 끌어다 놓기 → 표와 ✅/❌ 확인.
4. 첫 실제 시험은 **한 사이트만**: 기획 JSON을 `run_confirm.bat` 위에 끌어다 놓기 → 시간대 번호(1·2·3) → 올릴 곳 `1`(유튜브만) → 멈출 때마다 화면 확인 → 최종 단추에서 대표가 직접 [예약] → '완료' 입력.
5. 실행 후 `logs/` 스크린샷을 Claude에게 보여 주면 `TODO` 선택자를 실제 화면에 맞게 고친다.

## 9. 한계 (1차)

- 이 작업 공간에는 사이트 로그인이 없어 **실제 사이트 시험은 하지 않았다**. 사이트별 선택자는 화면 글자 기준 추정이며 `TODO`가 많다(특히 날짜·시간 고르기).
- 사이트 화면은 예고 없이 바뀐다. 바뀌면 프로그램이 멈추고 대표에게 넘기므로 잘못 누르지는 않지만, 그때마다 선택자를 고쳐야 한다.
- 실행 중에는 업로드 전용 크롬 창을 다른 일에 쓰지 않는다(같은 프로필을 두 번 열 수 없음).
- 휴대폰에서는 쓰지 않는다(데스크톱 전용). 휴대폰은 결과 확인·첫 댓글 고정만.
