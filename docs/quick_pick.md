# 후보 작업용 한 장 요약 (대표 결정 2026-11-02 09:10, 분석팀 · 토큰 절약)

후보 작업(평일·주말·밤 23:20·리센느)은 **이 파일만 읽는다.** 원문(docs/topic_pick.md, style/style_guide.md)은 여기 없는 판단이 필요할 때 해당 장만 연다. 원문이 바뀌면 이 요약도 같이 고친다.

## 0. 큰 원칙
- 후보만 올린다. 카드·영상·소개글은 만들지 않는다. 대표가 고른 것만 「고른 소재 만들기」가 만든다(①소재 선택 ②카드 확인 ③확정 ④재료함).
- 출처는 서로 다른 매체 2곳 이상을 **직접 열어** 확인한 것만. 정치·사회는 가능하면 성향이 다른 매체.
- 사진은 공식 출처만(기관·기업·구단·리그·소속사·방송사·관광청의 공식 유튜브 화면). 뉴스 통신사·언론사 사진, 인물 얼굴 위주 화면은 피한다. 후보마다 쓸 사진 검색어를 적는다.
- 빼는 것: 농구(KBL 등), 비방·사생활·열애·루머·선정적 소재, 확인 안 된 숫자. 사건·사고·정치처럼 민감한 소재는 빼지 말고 제목 앞에 "[민감]"만 붙인다(제외 여부는 대표가 정함).
- 최근 7일 posts/·rounds/ 주제와 겹치면 뺀다.

## 3. 손흥민(SON) 레전드 비교 특집
손흥민 기록을 이전 레전드(차범근·박지성·홍명보·이영표·기성용 등)와 **지표 하나**로 비교하고 숫자 뒤 감동 이야기로 끝낸다. 후보 3개 = 서로 다른 지표 3개(data/picks 의 지난 SON과 겹치지 않게). 대한축구협회·리그·구단 공식 기록 우선, 기준일 표기. 다른 선수를 깎아내리지 않는다. 대표팀 내부 갈등·호칭 논란·축협 비판은 다루지 않는다.

## 4. 리센느(RS)
- 우선순위: ① 새 소식(컴백·음원 성적·음악방송·수상·공식 일정·공식 챌린지·안원잘부 새 영상) ② 없으면 기록·데이터(곡 기록, 걸어온 길, 수록곡, 공식 일정 D-day). 같은 내용 일주일 안 반복 금지.
- 콘셉트 "광고 아닌 광고": 다 보면 곡을 들어 보고 싶게, 과장·최상급 대신 구체적 사실.
- 금지: 열애·사생활·루머·멤버 비교·다른 그룹 비하·팬덤 갈등. 이봐협·제3자 쇼츠는 힌트로만 쓰고 출처로 쓰지 않는다.

## 5. 정치·사회(POL·ECO)
사실만, 양쪽 입장을 같은 분량·같은 말투로. 확인 안 된 의혹은 "~라고 주장했다"처럼 누구 말인지 밝힌다. 국적·지역·성별·종교를 제목에 올리지 않는다. 우리 계정의 평가·편들기 금지.

## 6. 고르는 순서 (화제도 점수)
1. 점심·저녁은 구글 뉴스 한국판(https://news.google.com/home?hl=ko&gl=KR&ceid=KR:ko)을 한 번 열고 분야별 WebSearch 1~2번. 아침은 영어 top world news + "해외 한국인 활약".
2. 후보 5개를 6항목 0~3점으로 매긴다: coverage(다룬 매체 수 1~2곳 0 · 3~4곳 1 · 5~9곳 2 · 10곳+ 3), rankings(많이 본 뉴스 오른 곳 수), fandom(아이돌·스포츠 스타·화제작 3, 유명인 2, 기관·기업 1), ourHistory(config/topic_score.json 의 ourHistoryScale), freshness(오늘 3·어제 2·2~3일 1), shareable(정리·기록·반전 3 ~ 단순 사실 0). config/topic_score.json 가중치를 곱한 합계 순으로 기사 확인.
3. 민감·제외 기준이 점수보다 먼저다. 같은 점수면 해외에서 활약하는 한국인 > 따뜻한 화제 > 경제 기록 > 일반 뉴스.
4. 확인된 것만 분야마다 후보 2~3개.

## 7. 기록하는 법 (A단계)
1. PICKID = <YYYYMMDD>_<SLOT>_<KIND>(리센느는 <YYYYMMDD>_RS). 재료함 picks/PICKID 가 이미 있으면 끝.
2. 저장소 data/picks/PICKID.json = {slot, candidates:[{title, summary, facts:[확인한 사실 3~6개, 숫자·날짜], sources:[{outlet,title,date,url}], photoQuery, score}]}.
3. data/topic_log/<YYYYMMDD>.json 에 {slot, candidates:[{title, scores, total}], picked:null} 추가.
4. git add data/picks data/topic_log (scripts/__pycache__ 제외), 커밋 "소재 후보: <DATE> <SLOT>" + 빈 줄 + Co-Authored-By 줄, pull --rebase 후 push(최대 3번).
5. ArtifactData set 재료함 picks/PICKID = {date, slot, kind, slotName, makeAt:"바로", status:"waiting", candidates:[{title:"25자 안팎", summary:"숫자가 든 40자 안팎", why:"분야 · 화제도 점수 한 줄"}], createdAt}.
6. 알림: "🗳 <slotName> 후보 — 이슈브리프 대화에서 골라 주세요" + ①②③. 후보가 없으면 picks status "skipped" + "○○ 회차는 올릴 만한 소식이 없어 쉬어요".
7. 같은 내용을 재료함 reports 에 남긴다(각 작업 프롬프트의 [보고 위치] 문단대로).
