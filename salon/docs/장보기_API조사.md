# 단골 수첩 「장보기(샵)」 — 상품 검색·제휴 링크 API 조사 (2026-11-11)

- 목적: 원장님이 말로 조건을 말하면 → 우리가 상품을 찾아 **가장 싼 것 + 평점·리뷰 많은 것**을 추려 보여 주고 → 제휴 링크로 수익.
- 대표 결정(전제): 수수료는 원장님과 나누지 않음. "이 앱이 무료인 이유: 추천 링크 수수료"를 처음부터 공개. 추가 비용 0원. 화면 크롤링(스크래핑)은 약관 위반 위험이라 쓰지 않음.
- 표기: **[공식]** 운영사 페이지를 이번에 직접 열어 확인 / **[보조]** 블로그·개발자 패키지 설명(공식을 못 열어 참고만) / **확인 못 함**.
- 이 환경에서 **열리지 않은 공식 페이지**: partners.coupang.com, developers.coupangcorp.com(HMAC 문서), developers.naver.com(쇼핑 검색 문서), github.com/naver/naver-openapi-guide, m.oliveyoung.co.kr(큐레이터 신청·가이드, robots 차단). → 아래 「퍼플렉시티 질문 목록」으로 넘김.
- 법률 자문 아님. 제휴 약관은 가입 후 대표가 휴대폰에서 본문을 한 번 더 확인.

## 결론 먼저 (대표용 5줄)

1. **쿠팡 파트너스 검색 API는 있다**([보조] `GET /products/search`). 다만 **가입 → 실적으로 최종 승인 → Open API 키 발급** 순서라 바로는 못 씀. 키가 생겨도 **1분 50회**, 그리고 계정 전체로 **1시간 30회 넘으면 24시간 정지·3회면 계정 정지**라는 보조 자료가 있어 **반드시 서버 캐시 + 버튼 눌렀을 때만 호출**.
2. **쿠팡 검색 응답에 평점·리뷰 수가 있는지 공식으로 확인 못 함.** 보조 자료 2곳 중 1곳(n8n 패키지·블로그 코드)은 `productName·productPrice·isRocket·isFreeShipping·rank`까지만 있고, 다른 1곳(k-skill 프록시)은 `review_count·score`를 내보냄(프록시가 따로 붙였을 수도). → **"리뷰 많은 순"은 지금은 쿠팡 순위(rank)로 대신**하고, 필드가 확인되면 켜도록 코드에 자리만 둠.
3. **네이버 쇼핑 검색 API**는 무료 키로 **최저가(lprice)·판매처(mallName)**는 주지만 **평점·리뷰 수는 없음**([보조] 여러 예제 공통). 또 링크가 네이버 쇼핑/판매처 링크라 **우리 제휴 수익이 안 생김** → "가격 비교 참고용"으로만, 기본은 꺼 둠.
4. **올리브영 쇼핑 큐레이터**: [공식] 추천 상품 7%, 다른 상품 3%, 클릭 후 24시간, 누구나. 그러나 허용 채널이 "인스타그램·블로그·유튜브·틱톡 등" — **앱·개인 웹사이트 안 링크는 명시 없음**, 상품 검색 API도 **없음(공개 문서 없음)**. → 약관 확인 전에는 **손님 홈케어 추천을 원장님이 직접 고른 링크로 손으로 넣는 방식**만.
5. **오늘의집 큐레이터**: [공식] "내 SNS나 **개인 홈페이지**에 게시한 제품 링크" 허용, 3/4/5%, 상품 페이지 「공유하기」로 링크 발급. 검색 API는 **없음(공개 문서 없음)**. → 「매장 꾸미기」는 **우리가 고른 상품 목록(수동 큐레이션)**으로 시작하는 게 맞음.

**판매처 판단 한 줄**: 미용실 전문 재료(염색약·산화제·펌제·가위·호일·장갑)는 **쿠팡**(품목 폭·API), 손님 홈케어(샴푸·트리트먼트·에센스)는 **올리브영**(7%, 단 앱 게시 약관 확인 후), 매장 인테리어는 **오늘의집**(개인 홈페이지 허용이 공식으로 확인된 유일한 곳).

## 1. 쿠팡 파트너스 Open API

| 항목 | 내용 | 근거 |
|---|---|---|
| 검색 API 제공 | **있음** — `GET /v2/providers/affiliate_open_api/apis/openapi/v1/products/search?keyword=…&limit=…` (`subId` 선택) | [보조] n8n-nodes-coupang-partners 설명 https://www.pkgstats.com/pkg:n8n-nodes-coupang-partners · 블로그 코드 https://aboda.kr/?p=10746 |
| 그 밖의 API | `bestcategories/{id}`, `goldbox`, `coupangPL`, `reco`, 리포트(clicks·orders·commission), **`POST /deeplink`**(쿠팡 URL → 추적 단축 링크) | [보조] 위 pkgstats |
| 가입·승인 | 쿠팡 파트너스 가입 → 채널(웹사이트·앱 URL) 등록 → 심사 → 실적 발생 후 최종 승인 → Open API 키 발급(보조 자료에 "누적 판매 15만 원" 기준 언급 많음) | **확인 못 함**(공식 접속 실패). [보조] 이전 조사 `research/ads_research.md` 62행 |
| 호출 한도 | 검색 **1분 최대 50회**. 일반 API **1시간 30회 이상 → 24시간 정지, 3회 정지 시 계정 정지**. 리포트 1시간 500회 | [보조] pkgstats. **공식 확인 필수** |
| `limit` 최대 | 블로그 코드 기준 10 또는 30(자료마다 다름) | [보조] k-skill 문서(1~10), aboda.kr(30) |
| HMAC 서명 | `signed-date` = UTC `yyMMdd'T'HHmmss'Z'` / 메시지 = `signed-date + METHOD + path + query`(query는 `?` 빼고) / HMAC-SHA256(시크릿 키) → hex / 헤더 `Authorization: CEA algorithm=HmacSHA256, access-key={AK}, signed-date={date}, signature={sig}` | [보조] aboda.kr 코드. 공식 문서 주소 https://developers.coupangcorp.com/hc/en-us/articles/360033461914-Creating-HMAC-Signature (열리지 않음) |
| 응답 필드 | `data.landingUrl`, `data.productData[]` = `keyword, rank, productId, productName, productPrice, productImage, productUrl(이미 제휴 추적 링크), isRocket, isFreeShipping` | [보조] pkgstats·aboda.kr |
| 평점·리뷰 수 | **확인 못 함.** k-skill 프록시 문서에는 `review_count, score`가 나오나 프록시 가공일 가능성 | [보조] https://raw.githubusercontent.com/NomaDamas/k-skill/main/docs/features/coupang-product-search.md |
| 딥링크 | `POST /deeplink` 본문 `{coupangUrls:[...], subId}` → `shortenUrl, landingUrl` | [보조] pkgstats |
| 고지 문구 | "이 게시물은 쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다." (앱에 이미 쓰는 문구와 같음) | [보조] 이전 조사·공정위 추천보증 심사지침 |
| 약관: 가격 비교·캐시 | **확인 못 함.** 가격·재고는 수시로 바뀌므로 짧은 캐시(우리 초안: 30분) + "검색 시점 기준" 표시로 설계. 상품 이미지를 우리 서버에 저장하지 않음(쿠팡 이미지 주소를 그대로 표시) | 퍼플렉시티 질문 1~4 |

**우리가 쿠팡 검색 API를 쓸 수 있는 조건(정리)**
1. 쿠팡 파트너스 가입 + 채널로 **단골 수첩 주소(Netlify) 등록·승인**.
2. 우리 링크로 **실적이 쌓여 최종 승인** → Open API 키 발급. 그 전까지는 **mock(예시 데이터) + 대표가 손으로 만든 링크**로 운영.
3. 키는 **Netlify 환경변수**에만(코드·화면에 없음), 브라우저는 우리 함수만 호출.
4. 호출 아끼기: 같은 검색어는 서버 캐시, "찾기" 버튼 눌렀을 때만 호출, 1분 50회·1시간 한도 넘지 않게 함수에서 막음.
5. 결과 맨 위에 쿠팡 파트너스 고지 문구 원문 + "가격·평점은 검색 시점 기준".

## 설계에 반영한 것

- 프런트 `SEARCH` 어댑터: `mock`(지금) | `netlify`(키 생긴 뒤). 모든 결과는 공통 형식 `{source, id, name, brand, price, unitCount, rating, reviews, shipping, url, image, store}` — **source = coupang | oliveyoung | naver | ohou**, 카드에 판매처 표시.
- 평점·리뷰가 `null`이면(쿠팡 미확인, 네이버 없음) 점수에서 해당 항목을 빼고 "평점 정보 없음"으로 표시. 「리뷰 너무 적은 상품 제외」는 리뷰 수가 있는 상품에만 적용.
- 서버 함수 `netlify/functions/shop-search.js`: 키는 환경변수, 같은 검색어 30분 메모리 캐시(약관 확인 전 기본값, 환경변수 `SHOP_CACHE_SECONDS`로 0 가능), 쿠팡 1분 45회 자체 제한, 실패 응답은 캐시 안 함.
- 크롤링 없음. 이미지 파일 저장 없음.
